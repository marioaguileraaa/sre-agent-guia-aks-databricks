## Step 1 - Permissions for the agent managed identity

All access is read-only except publishing the report. Run in Azure Cloud Shell (bash) unless stated otherwise.
Find the identity in the SRE Agent portal: **Settings > Azure settings > Managed Identity > Go to Identity**; the Azure portal
Overview page shows the **Client ID** and the **Object (principal) ID** used below.

**1. Reader** - scope `/subscriptions/<subscription id>` - read resources for source 'disks'

```bash
az role assignment create --assignee-object-id <agent managed identity principal (object) id> --assignee-principal-type ServicePrincipal --role "Reader" --scope "/subscriptions/<subscription id>"
```

Role assignments take 5-10 minutes to apply; Microsoft Graph app roles can take up to 30 minutes.

## Step 2 - Python tool

**Builder > Agent Canvas > Create (arrow) > Tool > Python tool**

- Name: `run-orphaned-managed-disks`
- Description: copy from `orphaned-managed-disks-BUILDER-BLOCKS.md`, block 1
- Timeout: 300 seconds
- Parameters:

| Name | Type | Default | Description |
|---|---|---|---|
| `mode` | string | report | report = full HTML/CSV/JSON report; discover = read a few live rows per source and list columns (no report); self_test = simulated data, no Azure calls, proves the logic and HTML |
| `publish` | string | no | yes = also upload the report and its snapshot to the configured SharePoint/Blob target (history for next comparison); no = thread only |
| `lookback_days` | integer | 0 | Days of data to analyse; 0 = CONFIG default |

- Code: paste the whole content of `run-orphaned-managed-disks.py`. Only edit the `CONFIG = {...}` section if you need to change queries, thresholds or rules.
- Identity tab: leave **Enable Azure Identity** OFF. The code uses the agent managed identity of the sandbox.
- **Create tool** stays disabled until you run a test in **Test playground**.

In **Test playground**, click **Test** in this order and keep each result:

1. `mode=self_test` -> `status: SIMULATED` and an HTML link (proves the logic without Azure access).
2. `mode=discover` -> every `sources[].status` is `OK` and you see the expected columns. A `FORBIDDEN` means step 1 is missing.
3. `mode=report`, `publish=no` -> `status: OK`, KPIs and findings make sense, open the HTML.
4. `mode=report`, `publish=yes` (only if publishing is configured) -> `published[].status: OK`.
